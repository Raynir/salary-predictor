# Company USD rate predictor

A static web page that predicts the company's monthly USD→RUB rate from the Central Bank (CBR) daily rates and estimates a salary under a rate-linked multiplier scheme. UI in English and Russian. People get it as an archive with `predictor.html` and `src/` and open the HTML file by double-click (file://), or use the GitHub Pages copy that `.github/workflows/pages.yml` deploys from each published release. No server; everything must keep working on file://.

## Layout

```
predictor.html        markup: sidebar + five sections (forecast, salary, salary-history, earnings, settings)
src/styles.css        all styles; color tokens on :root with dark-mode overrides
src/data.js           GENERATED by update_data.py: const EMBEDDED = {cbr, company, holidays, builtAt}
src/js/i18n.js        T.en / T.ru strings, store (localStorage), tr(), fmt(), $()
src/js/util.js        date helpers, CSV parsing
src/js/tax.js         progressive income tax: brackets editor, year-to-date withholding
src/js/model.js       data state S, predict(), backtest()
src/js/forecast.js    forecast section, applyLang(), render() (the main redraw)
src/js/rate-chart.js  rate history chart
src/js/salary.js      salary calculator and multiplier explainer
src/js/salary-history.js  salary history chart and table
src/js/calendar.js    production calendar: holiday file parsing, working days, pay dates
src/js/earnings.js    earnings section: salary periods, vacations, pay schedule, year calendar
src/js/stats.js      opt-in salary statistics: first-launch dialog, settings card, POST to Apps Script
src/js/data-sync.js   status line, online refresh from cbr-xml-daily.ru, CSV file loading
src/js/nav.js         sidebar section switching (URL hash + sp.section)
src/js/main.js        event wiring and startup
data/*.csv            source data: CBR daily rates, company monthly rates (header only in the repo), production calendar (holidays.csv)
private/              gitignored: real company_rates.csv and scheme.json (pay-scheme defaults), used by make_zip.py
.github/workflows/pages.yml  on a published release: rebuild src/data.js at the tag, build the site with `make_zip.py --site` (SAL_DEFAULTS from the SCHEME_JSON secret), check no stats URL or company rates are in it, deploy to GitHub Pages
tools/stats-apps-script.gs  Google Apps Script backend for the statistics (pasted into the sheet, not loaded)

make_zip.py           builds dist/*.zip to hand out, filling STATS_URL from stats_url.txt, company rates and SAL_DEFAULTS from private/ (all gitignored); --with-sources adds data/, update_data.py, README; --site DIR writes the public web copy (SAL_DEFAULTS only)
```

## Rules

- No dependencies, bundlers or frameworks. Python scripts use the standard library only (3.8+).
- Scripts are classic `<script src>` tags sharing one global scope. ES modules and `fetch` of local files fail on file://, so don't use them. A file may only use top-level names from files loaded before it, unless the use is inside a function called later. Keep the `<script>` order in `predictor.html` in sync.
- Never edit `src/data.js` by hand. Edit `data/*.csv` and run `python update_data.py` (`--no-fetch` to skip the network).
- Every UI string goes in both `T.en` and `T.ru` in `i18n.js`. Static text uses `data-t="key"`; `applyLang()` fills it.
- The prediction model exists twice: `src/js/model.js` and `update_data.py`. Change both together and keep their output equal.
- Colors only through the CSS tokens in `styles.css`. Check light and dark themes.
- localStorage keys use the `sp.` prefix and go through `store`.
- Charts read `svg.clientWidth`, which is 0 inside a hidden section. `showSection()` redraws them; any new chart needs the same.
- `STATS_URL` in `src/js/stats.js` stays `""` in the repo; `make_zip.py` fills it in the archive only. Never commit the real URL.
- The repo is public. Real company rates and pay-scheme numbers stay in `private/`: `data/company_rates.csv` keeps only its header, `src/data.js` is always built without company rates, and `SAL_DEFAULTS` in `salary.js` holds example values.
- Keep the README (English and Russian halves) current when behavior changes.

## Checking changes

1. `python update_data.py --no-fetch` should run cleanly and print a prediction.
2. Open `predictor.html` in a browser. Go through all five sections, switch EN/RU, try a narrow window (under 720px the sidebar turns into a top tab bar) and check the console for errors.
3. Headless check without a GUI: `chrome --headless=new --virtual-time-budget=4000 --dump-dom "file:///<abs path>/predictor.html#forecast"` and look for the rendered values, or use `--screenshot`.
